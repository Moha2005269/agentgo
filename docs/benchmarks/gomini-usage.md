24 form tasks (`tests/fixtures/pages/gomini-bench.html`, seeds 1-24): 2-4 fields, some lists, 18-68 other links and filler text per page. Tokens are characters / 4 of what the agent's model reads (tool results as AgentGo's MCP server renders them) and writes (tool arguments). Run with `node scripts/dev/gomini-bench.js`.

| Mode | Model reads (tokens, total) | Model writes | Turns (total) | Tasks done | Browser time |
|---|---|---|---|---|---|
| A raw HTML | 186,645 | 1,072 | 120 | 24/24 | — |
| B1 AgentGo, step by step | 9,515 | 1,072 | 120 | 24/24 | 2192 ms avg |
| B2 AgentGo, one batch | 9,203 | 1,142 | 48 | 24/24 | 2151 ms avg |
| C GoMini, one delegation | 1,424 | 2,071 | 24 | 24/24 | 2861 ms avg |

- AgentGo alone (B1 vs A): the model reads 19.6x less.
- GoMini (C vs B1): 6.7x less to read and 5.0x fewer turns; vs the best manual use (B2): 6.5x less to read, 2.0x fewer turns.
- GoMini model time: 274 ms per task (120 decisions in all). Each turn saved is one fewer round trip to the agent's large model, which takes seconds.
- Scope: these are AgentGo form pages of the kind GoMini was trained on; they show the savings and that the checks hold, not GoMini's accuracy on arbitrary websites. Characters / 4 is an estimate of tokens; the ratios between modes are what matter.
- GoMini never pressed Publish: yes. Not done: none.
