Status and roadmap

Known limits and open points

  • Google shows a CAPTCHA to brand-new profiles after many automated runs. AgentGo hands it to the person (by design, never solved); the person's real profile, or Bing/DuckDuckGo in Settings, avoids most of them.
  • Extensions run their content scripts only; toolbar buttons, pop-ups, background workers and native messaging of Chrome extensions are not part of the embedded engine.
  • OAuth API connectors were tested end to end against a mock provider (PKCE, refresh, forged and replayed answers). Real Google, GitHub and Yandex sign-in needs the person's own OAuth client id and was not tried live.
  • Camera, microphone and location now ask the person; notifications are still refused by the embedded engine even when granted.
  • Some older end-to-end files (ui_surface_smoke, windows_e2e, rest_e2e) were not re-run for this release; the Rust suite and the files listed in the changelog were.
  • The VPN was removed from this release; the Settings card says "coming soon".
  • The ad blocker bundles EasyList (CC BY-SA 3.0 / GPLv3) as data; notices ship in licenses/.
  • The executable is not code-signed; Windows SmartScreen may ask once. There is no auto-update.
  • Every open tab keeps rendering so agents can work in background tabs; very many tabs cost memory.

Next phase: Laya and the experiment

The browser is ready for the graduation experiment (configurations A, B, C0, C1). What is already in place for it:

  • Decision record (decision.record / decision.apply, schema agentgo.laya.decision/0): the subgoal, compact state, every possible step as a candidate, supplied values and recent outcomes — exactly what Laya will be given. Documented in skills/agentgo/references/laya.md.
  • Training data: workflow.record writes every step, including full decision records and their outcomes, as JSON lines.
  • Measurement: metrics.* (latency, errors, recoveries, handoffs, reply tokens, task success, tokens per success, turns) and benchmark.* (record, compare, regression, replay a recording N times).
  • Setting: "Laya, the local choice model" in Settings (off by default; your own model decides when it is off).

Still to do: build the local worker that loads a Laya checkpoint and answers decision records; collect trajectories; fine-tune; run the A/B/C0/C1 comparison (BrowserGym tasks plus AgentGo fixtures).

Starting again

  • Read README.md, then docs/HANDOFF-OPUS.md and docs/issues-log.md (every problem met and how it was solved).
  • Build: powershell -File scripts\build.ps1 -Runtime (CEF is fetched by scripts\bootstrap.ps1 from scripts\pins.json). Test: node scripts\dev\run-integration.js. Package: scripts\package.ps1 -Release.
  • Add a tool: one line in scripts/dev/tools-spec.js (plus a function in tools.js if it reads the page), then gen-tools.js, gen-skill.js, build, tools_e2e.
