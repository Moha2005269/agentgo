# AgentGo — issues and failures log

Running record of every defect, failure and dead end found while auditing and
finishing AgentGo, with how each was resolved or worked around. Source material
for the final project report. Newest entries at the bottom of each section.

Status: `FIXED` (verified), `WORKAROUND` (bypassed, root cause remains),
`OPEN` (known, not yet resolved).

## A. Found during the Milestone 0–3 audit (2026-10-06)

| # | Area | What was wrong | How it was found | Resolution | Status |
|---|---|---|---|---|---|
| A1 | Build | `cargo test --workspace` / `cargo build` silently overwrote `target\debug\agentgo.exe` with a CLI-only binary that exits with code 2 on `run`. The docs called this a "launch/build guard" instead of fixing it. | Ran the documented test command, then the protocol smoke: every request timed out with "agentgo run needs the native runtime build". | Split the binaries: `agentgo` (the browser) now requires the `runtime` feature, repository tooling moved to `agentgo-tool`. A plain workspace build can no longer produce a fake `agentgo.exe`. | see log below |
| A2 | Tests | `protocol_smoke.js` failed on the current tree although milestones.md recorded it as passing. It listed downloads before the fixture page's own delayed auto-download fired (race), and asserted on the wrong record. | Ran the smoke; assertion `expected the local download fixture to be recorded`. | Test now polls for the record instead of reading once. | see log below |
| A3 | Profiles | Profiles never persisted. The content request context used `…\profiles\default` two levels below CEF's root cache path; CEF requires a direct child and logged `Cannot create profile at path` on every launch, then silently fell back. On top of that the root itself was a new `%TEMP%\agentgo-runs\<pid>-<nonce>` directory per launch, so cookies and logins were lost on every restart and temp directories leaked forever. Milestone 2 was marked complete with "preserving cookies and site data across launches" in a code comment. | CEF stderr during every smoke run. | Persistent per-profile root under `%LOCALAPPDATA%\AgentGo\profiles\<id>\cef` guarded by a lock file; a second instance or an agent launch without `--profile` gets an explicitly reported ephemeral root that is deleted on exit; stale run directories are swept at startup. | see log below |
| A4 | Architecture | Every command was implemented twice: ~400 lines in `scheme.rs` for the shell bridge and again in `state.rs` for stdio. The master plan (M3) forbids a separate privileged implementation. The two copies had already drifted (different error codes for the same failure). | Code review. | One async dispatcher (`runtime/dispatch.rs`) used by stdio, the named pipe and the shell bridge. | see log below |
| A5 | Threading | The bridge ran on CEF's I/O thread and called UI-thread-only browser APIs directly for pointer, keyboard and download commands. | Code review of `scheme.rs` against CEF threading rules. | Bridge requests are now completed asynchronously on the UI thread through the shared dispatcher. | see log below |
| A6 | Memory | Every bridge response was copied into a process-lifetime `KEEPALIVE` vector and never freed — unbounded growth proportional to UI activity. | Code review. | Bridge replies use the same owned-buffer resource handler as bundled assets. | see log below |
| A7 | Honesty of UI | The New Tab page was still the prototype: the omnibox ran a 600 ms fake loader and showed an invented "generic" page with random latency/size numbers; fake agent log lines, fake "TLS 1.3 / lat 17ms / mem 428mb / v1.0.4" status bar, hard-coded "Codex/Claude Code connected" agents, fake task progress, fake "up to date" update check. This violates the plan's central rule (no timers/toasts standing in for behavior). | Screenshot of the running browser through the new `scripts/dev/shot.js` harness plus reading `ui/index.html`. | New Tab rebuilt on real state only (see log below). | see log below |
| A8 | History | History entries stored the URL as the title; tab labels showed only the host. No title or favicon plumbing existed. | Code review + screenshot. | Display handler feeds real titles/favicons into tabs and history. | see log below |
| A9 | Security | Any protocol caller could flip `downloadsEnabled` (and `controlMode`) through `settings.set`, although the plan and a code comment say only the operator may. The smoke test itself relied on this hole. | Code review + smoke test source. | Operator-only settings are rejected for agent callers; tests use the operator launch flag `--allow-downloads`. | see log below |
| A10 | Input | `pointer.*` / `keyboard.*` used CEF `send_mouse_*`/`send_key_event` and reported `accepted:true` without any evidence the page received the event. The smoke test only asserted the echo. | Code review. | Input now goes through the DevTools Input domain and a fixture page asserts the page actually received trusted events. | see log below |
| A11 | Docs | `milestones.md` marked M1 and M2 "COMPLETE" while the above were broken; README still said "Milestone 0". | Audit. | Status documents rewritten from verified evidence only. | see log below |
| A12 | Milestone 3 | Not started: no named pipe, no authentication, no sessions or leases, no events, no CLI client. | Audit. | Implemented (see log below). | see log below |

| B9 | Clicking a button that calls `alert()` timed out after 15 s. | The renderer blocks inside the click handler until the dialog is answered, so the input event never returns; any later evaluate would block too. | Input calls stop waiting as soon as a dialog-opening event arrives; observation and actions report the open dialog and require `dialog.accept`/`dialog.dismiss`. | FIXED |
| B10 | Middle-click produced no `auxclick`; right/middle clicks reported the wrong `buttons` mask. | The pressed-buttons mask was hard-coded to the left button. (Chromium also starts autoscroll on middle-down, which suppresses `auxclick` on non-links for a human too.) | Correct masks per button; the test asserts the `mousedown` the page really receives. | FIXED |
| B11 | An agent that did not name a tab acted on whatever tab was globally visible — including another agent's tab (then failed with a lease error). | Default tab was the active tab. | Each session defaults to the tab it used last; only the human's chrome defaults to the visible tab. | FIXED |
| B12 | A test run appeared to hang at shutdown for 25 s and reported only "exit code timeout". | An earlier assertion had failed while agent control was Stopped; the cleanup's `browser.shutdown` was (correctly) refused for a stopped agent, and the cleanup error masked the real one. | The process that launched the browser over stdio may always shut it down; tests print the original failure before cleanup. | FIXED |
| B13 | Shell heredocs containing apostrophes or backticks failed to parse in the tool shell, aborting multi-file edit scripts halfway. | Tooling limitation of the command wrapper. | Edit scripts are written to files first and then executed. | WORKAROUND |
| B14 | The handoff notification shows the generic executable icon instead of the AgentGo logo. | The executable has no icon resource; the notification uses `IDI_APPLICATION`. | Embed an AgentGo icon resource and use it for window, taskbar and notification. | OPEN |
