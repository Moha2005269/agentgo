# Changelog

## 0.1.6 (2026-10-22)

Single-page apps: references that survive re-renders, one-call scrolling
and waiting, and actions that say what must happen. The fixes come from a
new benchmark of client-side-rendered pages (`docs/benchmarks/agentgo-spa.md`)
and from benchmarking AgentGo with and without GoMini on MiniWoB++, the SPA
set and 232 more MiniWoB++ runs; the numbers are in
`docs/benchmarks/agentgo-0.1.6.md`. Measured with one model on 38 tasks, all
four setups at the same time (76 runs each): wrong actions 6 -> 0 with GoMini
and 2 -> 1 without, success with GoMini 86.8% -> 94.7%, and without GoMini
16% fewer input tokens per solved task, 14% fewer turns and a 10% lower
median time. Next to Playwright MCP and browser-use on 37 tasks, all four at
the same time: AgentGo 0.1.6 with GoMini v6 37/37, AgentGo 0.1.6 37/37,
browser-use 35/37, Playwright MCP 31/37, with AgentGo using 95-114k input
tokens per task against 227-306k. The harness is in `benchmarks/`.

- **A reference no longer clicks the wrong row after a re-render.** A list that re-renders by position (React's `key={index}`, a recycled virtual row) puts another item into the same DOM node; 0.1.5 clicked whatever the node showed. A reference to a repeated control now remembers its row: if the node shows another row, the action goes to the element that shows the original one, or fails with `target.stale` saying what the node shows now. A click also re-aims right before pressing, so a row inserted during the pointer animation does not take the click (a stress test clicking across inserts: 10/10).
- **Repeated controls say which row they are in.** Buttons that read the same, numbers aside ("Dismiss", "Like (12)", "Select"), carry their row in the outline, change sets, GoMini's choices and action replies: `button "Dismiss" in "Invoice #4471 is overdue"`. The agent no longer counts buttons to match them to rows. A box with more than three controls (a tree, a menu, a form) is not a row; a menu item's wrapper is no longer listed next to it.
- **Long lists in one call.** `browser_act {action: "scroll", until: "<text>"}` scrolls the page, or the list `ref` is in, until the text shows, waiting for lazy and infinite lists to load (a 300-row virtual list: 249-400k input tokens and 86-126 s per task before, 59-78k and 35-40 s now). Plain scrolling moves the main list when the page itself cannot scroll; with `ref` and `to: top|bottom` it scrolls inside that box (a textarea).
- **Waiting on what matters.** `browser_wait {enabled: <ref>}` waits for a control to become usable, `{ms}` pauses (also as a `browser_batch` step, counted from the last input, so "click, wait one second, click" keeps its timing), `gone` takes a text as well as a selector, texts are matched as the outline writes them, and a met wait returns its change set, so no read is needed after it.
- **`expect` on actions.** An action can say what must hold once it ran: `expect: {gone, shows, enabled, url, changes}`. The reply says `expect: met`, or the action fails saying what was expected and what did change, so a click on a page that has not hydrated yet cannot pass as "no visible change".
- **Replies show the next view, not its spinner.** After an action AgentGo waits for the fetch/XHR requests it started, then for the page to draw them; settling on pages that never go still is capped at 1.5 s (was 2.5 s). The drawn pointer and typing take half as long.
- **A short guide in tool names.** Over MCP, `browser_guide` answers with 3k characters about `browser_open`, `browser_act` and the rest (the 8.8k-character shell guide named protocol methods, which sent agents into `browser_call` loops: 44 calls and 1.5M tokens on one task); the full guide is `topic: "skill"`. The server instructions carry the rules that save turns and no longer ask agents to read the guide first.
- **Reading code and long text.** `browser_read {view: "text"}` includes text boxes and code views (GitHub's file view), `filter` returns the lines that hold it with their line numbers, and `offset` and `max` count lines, as in the outline.
- **Element fingerprints ignore state** (disabled, checked, expanded), so a button found again after a re-render is the same button.
- **GoMini v6**, which 0.1.6 downloads (existing installs update once): trained further from v5 on 29,000 decisions, among them 12,000 new ones on AgentGo 0.1.6's practice pages (rows of identical buttons, scroll until found, retry after an error, dialogs that cover the page, wait until enabled, "the 3rd option", focus a box, collapsed sections) and 577 steps of gpt-6-luna on MiniWoB++ pages it solved. Held-out practice pages: 96.6% (v5: 76.6%; retry 33% -> 100%, rows 59% -> 100%, wait 59% -> 100%).
- **GoMini's supervisor**: "done" before any step ran is replaced by GoMini's most likely step when it is a real contender (focus-text 0/5 -> 5/5); a subgoal with nothing to type whose next step is the planner's ends `done`, naming that step; a finished delegation returns the page changes since the planner last looked; "focus the text box" offers boxes as clicks. GoMini is described for runs of steps, not single clicks.

## 0.1.5 (2026-10-21)

Agents see more of the page, act on it correctly, and spend fewer turns and
tokens doing it; GoMini v5 takes far more steps right. The fixes come from
benchmarking AgentGo on BrowserGym's MiniWoB++ suite, 20 popular websites and
an input-type test page; the numbers are in `docs/benchmarks/`.

- **`browser_open` answers with the page you will act on.** It returned before the page's load handlers ran (on all 130 MiniWoB++ pages the first outline was the empty starting page) and, on a first visit to sites behind a browser check (Stack Overflow, Booking.com), with the empty page the check left behind. It now waits until the page is still (at most 0.8 s more), reads the real page after a check passes, and reads an empty page once more before answering.
- **Script-driven controls are in the outline.** Icons, calendar cells, chart slices and other elements that a page makes clickable with a script (no text, no pointer cursor) were missing: 380 of them across 79 MiniWoB++ pages, and 13 pages showed no controls at all. AgentGo now asks Chromium which elements have click listeners and lists them, named by their id or class (`clickable "(icon: like)"`). Clickable headings (accordion sections) are controls too.
- **Controls say which row they belong to.** A "+", "×" or icon now reads `button "+" in "Chicken wings"`; a menu item with a submenu says `haspopup`; a read-only picker field says `readonly`; a popup's question is shown (`dialog "Your session is about to expire."`), as are date pickers' month headings; fields labelled by a text before them (no `<label>`) carry that text as their name; a link without an address is `clickable`, not `generic`.
- **The outline says exactly what is there.** Field values are shown as they are (a trailing space is part of the text an agent copies; 0.1.4 trimmed it); a sentence keeps the number in its own inline element ("lower than 5."); an open list (`select multiple` or with a size) is a `listbox` with its chosen values and a preview of its options; radio buttons nothing names read "1 of 3"; a field alone in its own box is named by the text before the box; an open tree folder is named by its own label, not its children's, and is listed once; a menu row and the wrapper of its text are one line, and a drawn shape with a label drawn on it (a pie-menu slice) is one line named by the label that clicks the shape; a field is no longer named after the whole page around it; a tree item that holds a nested list says `collapsed` or `expanded`, so an agent opens folders instead of clicking files to find out; `browser_read view:"forms"` shows values exactly and in full (up to 2,000 characters); a calendar's Prev and Next (links without an address) are controls, and its heading keeps the year.
- **Autocompletes and lists.** After typing into a field that suggests, the reply waits for the suggestions (scripts show them after a delay), so they are in the change set; a click on a control that an open suggestion list covers closes the list with Escape first, as a person does (the click went to the list, or was refused). `act.select_option` takes `values: [...]` to choose several options of a multiple list.
- **Date, time, month, week, colour and range fields can be filled.** `act.fill` set nothing on them; it now sets the value with the page's input and change events, and accepts the usual written forms (`09/20/2019`, `4:15 PM`, `#369`).
- **`act.type` types where you point.** It ignored `ref` and typed into whatever had the focus, and it inserted text without key events, so pages that listen for keys (terminals, some autocompletes) saw nothing. It now focuses `ref` (or clicks it, for a terminal-like box), puts the caret at the end and types real key presses.
- **A newsletter "Subscribe" box is not a payment.** "Subscribe", "Donate", "Bid" and a ticked box only count as paying when a price is in sight; before, ticking a newsletter box asked for a payment approval in every mode.
- **CI**: the dependency audit passes again: `rustls-webpki` 0.103.16 and `webpki-roots` 1.0.10 (RUSTSEC-2026-0381, RUSTSEC-2026-0382).
- **Fewer tokens per step.** Action replies no longer repeat the page's standing signals (`"login": true` on every reply of a page with a password field); a short page (under 800 characters of text) is shown whole in one read; `browser_guide topic=commands` returns an index and finds commands by `query` instead of a 93,000-character list (`group: "all"` still returns it); actions on pages that do not react answer about 100 ms sooner. Change sets list removed references as ranges (`- [215]-[245]` for a redrawn calendar month) and count removed text lines instead of repeating them, a change of the address's `#fragment` only answers with a change set instead of the whole page, a row's context is added only for icons and symbols, and `browser_guide` with a `query` alone searches the commands, best matches first (12 rows).
- **GoMini v5**: trained further on 15,700 decisions recorded on AgentGo's own practice pages (forms, tabs, trees, menus, icons, check lists, sign-ins, payment buttons). On held-out practice pages it chooses the right step 96% of the time (v4: 49%); on held-out MiniWoB++ pages it finishes 39 of 65 subgoals (v4 with 0.1.4: 15) with 3 false "done" (v4: 26), and it still passes AgentGo's 24-form benchmark and the install self-test. Existing installs download v5 once.
- **GoMini's supervisor**: "done" counts only after a step ran or when every supplied value is in its field; while a value is missing, the step that fills it comes before any click; a value already in its field is not typed into another; subgoals in plain words ("fill the Username field with user=user") bind values to fields; the shortlist keeps tabs, tree items and "more" menus that lead to a named target; a click on the control the subgoal named in quotes finishes it; date values typed in another format count as filled; a radio button is chosen, never cleared; a check box is ticked, never cleared by choosing it again (it looped on two boxes), unless the subgoal says to clear it, and a subgoal that names its boxes in quotes ticks only those and is done once they all are; a read-only field (a date picker's box) is clicked, not typed into; a target covered by the control that opens it (the "+" of a closed menu) is reached by pressing that control first; when what is left is the planner's (send, submit), `done` names that control with its reference, and steps held for the planner say `held`; the evidence of a `needs_help` shows the page after the last step.

## 0.1.4 (2026-10-19)

The complete release: real Chrome extensions, customization, faster agent
browsing, an installer that closes when you ask, and the security fixes from
two code reviews of 0.1.3.

- **Chrome extensions run in Chromium's own extension engine.** Web Store extensions now run their background service worker, their content scripts at every `run_at` (including `document_start` and the page's main world), `chrome.storage`, `chrome.runtime` messaging, alarms, network rules (`declarativeNetRequest`: uBlock Origin Lite blocks with its 300,000 rules) and their real pop-up and options pages (`chrome-extension://`). AgentGo keeps the package's signing key in the unpacked manifest so each extension keeps its Web Store id; extensions installed by older versions are fetched again once, with their key, in the background. A new or re-enabled extension's page scripts run at once and the rest after a restart (Extensions > Restart now; your tabs come back). Folders without a key keep AgentGo's own content-script runner. Pop-ups get `chrome.tabs.query` answered with the tab they were opened over, and `chrome.tabs.create` / `openOptionsPage` open AgentGo tabs. Not yet: tab APIs that address one tab by id from the background (`tabs.sendMessage`, `scripting.executeScript`), because this engine lists only one Chrome-style tab per window and AgentGo shows many; extensions built on those (Dark Reader) apply partly.
- **Make it yours**: an accent colour (nine presets or any colour) that recolours the toolbar, panels, New Tab page and error pages; page text size (small to larger) for new tabs; search with Google, Bing, DuckDuckGo, Brave, Ecosia, Startpage or your own search address (`%s` where the words go); a home page for the Home button and "On startup: home page". All are in Settings and found by its search.
- **Faster on websites**: `navigate.url` answers as soon as the page is parsed and has been still for a moment instead of waiting up to 20 seconds for the last tracker or video (`usable: true` in the reply; `wait: "load"` waits for everything). The ad blocker's generic hiding rules are built once instead of on every page load.
- **No more false "human verification"**: sites that load an invisible reCAPTCHA or Turnstile frame (Reddit, The Verge and many others) were reported as CAPTCHA pages, which stopped agents and waited for the person. Only a challenge a person can see counts now.
- **Agents' clicks reach the page in a covered window.** Chromium treated a browser window that sat behind other windows as hidden and dropped pointer input to its pages, so an agent working in a browser the person had opened clicked, checked and pressed nothing (the commands still answered "accepted"). A covered window now stays a visible one, a minimized window comes back behind the person's windows (without the focus) when an agent acts, and `act.check` reads the box back, clicks the element directly if the click did not take, and reports the state the box really has.
- **GoMini, tested end to end with a planner**: "done" counts only when every supplied value is in its field (it could report done after typing nothing), and is reported once only a final step (submit, pay, sign in) is left, which stays the planner's; field names from the subgoal match labels with punctuation ("Telephone=phone" now binds to "Telephone:"), and a value bound to one field is not offered for others (it typed a phone number into "Delivery instructions"); `decision.apply` reads the page at the same size as `decision.record`, so pages longer than 120 lines no longer make every step "stale"; a step refused because the page moved on is tried again instead of ending the run.
- **Fields a site swaps out on focus** (Wikipedia's search box) are followed: the typing goes to the field that took the focus and the reference moves with it.
- **Approvals work from the shell**: a one-shot `agentgo call` ends right after the action that asked, which also dropped its approval, so a shell-based agent could never finish an approved step. Approvals of one-shot calls now survive until used or expired (still bound to the tab, site and control).
- Page text keeps the space between inline elements ("Chromium Embedded Framework", not "ChromiumEmbeddedFramework").
- Pop-ups of extensions see the address of the page they were opened over, never AgentGo's own error-page address.
- **AgentGo Setup closes when you click ×** during the download or the install: the window goes at once, the install stops at its next step, removes what it wrote and puts any previous copy back. Progress no longer floods the window (it queued thousands of updates during a fast download, which is why the close button seemed dead), and stalled downloads time out instead of hanging.
- **Extensions panel**: an extension without a pop-up showed a line of code instead of its buttons, and the Options button never appeared next to Open. Both fixed.

Security fixes from the code reviews of 0.1.3:

- **Saved passwords stay hidden from agents.** `credentials.fill` already typed a sign-in without returning it, but other commands could read it back. Now password fields cannot be read with `runtime.get_property`, `runtime.read_property`, `runtime.get_attribute` or `edit.cut`; `network.request_body` and `network.response_body` replace a typed password with `[hidden]`; page script (`runtime.evaluate`, `runtime.call_function`, `runtime.add_init_script`, `runtime.message` with data) is refused on the site where a password was typed; and `credentials.fill` refuses a tab with network interception rules, whose page an agent could have written itself.
- **`runtime.set_property` sets plain state only** (`value`, `checked`, `selectedIndex`, `title`, `textContent`, scroll and media properties, …). Markup, addresses, event handlers and an input's `type` are refused: they could run page script without the `runtime.evaluate` gate. Payment fields still go through `act.fill` and its approval.
- **AgentGo Setup checks a signature.** The online installer now installs only a package whose SHA-256 matches the release's `update-manifest.json` signed with AgentGo's release key (the key in-app updates already require). A missing checksum or `SHA256SUMS.txt` stops the install instead of being skipped, and link entries in a package are never unpacked.
- **Updates roll back cleanly.** If a file is still in use while the old version is moved aside, both the portable swap and Setup's update put everything back instead of leaving a half-moved folder; the portable swap also waits for AgentGo's helper processes to exit.
- **Agent connections**: a named-pipe handle is closed only after its writer is done, so a late reply can never reach another client's pipe. The SDK HTTP server bounds each header line to 8 KiB and no longer panics when a socket cannot be cloned.
- **GoMini** starts its local worker with a random API key: other programs and web pages can no longer use the model on 127.0.0.1.
- **Error pages**: a website can no longer open AgentGo's own error or "dangerous site" page with text of its choosing.
- The Windows UI Automation helper script is checked before every run and replaced if it was changed. Update version checks treat `1.2` and `1.2.0` as equal and a pre-release as older than its release.
- CI: a Linux job runs format, clippy, the portable crates' tests, the UI script check and `cargo audit`; GitHub Actions are pinned to commit SHAs.

Fixes from a second, deeper review:

- **Payments ask you, whatever the input.** Clicks, taps and pen strokes by screen position (`pointer.click {x, y}`, `act.click {x, y}`, `touch.*`, `pen.down`, `pointer.down`) now check what is under the point and need the same approvals as a click on a reference: money always, a final form submission in approval mode. Enter or Space on a focused button, `act.type`/`keyboard.*`/`clipboard.paste` into a card field, and `act.expand` on a paying or submitting control are checked the same way. Payment buttons are recognised in more languages (German, French, Spanish, Portuguese, Italian, Dutch, Swedish, Polish, Russian, Japanese, Korean, Chinese, Arabic, Turkish), and card fields in a payment provider's frame (Stripe, Adyen, Braintree and others) count as card fields.
- **Agents change only how the browser looks.** `settings.set` from an agent now accepts an allow-list (theme, accent, motion, favorites bar, home and extensions buttons, site dark mode, translation language) and refuses everything else. Before, settings missing from a deny-list could be changed, including the person's list of sites agents may not use, the agent's visible pointer and typing, keyboard shortcuts and the sync folder.
- **Sync and profile import cannot switch security settings.** A sync folder or an imported profile brings in only the look and plain preferences (search engine, startup, languages, hardware acceleration, notifications, offer to save sign-ins); control mode, script evaluation, other programs, downloads, privacy protections and the agent site lists stay as they are. Restoring your own checkpoint still restores everything.
- **Downloads are read-only for agents.** Agents write, move, rename, redact and delete files only in their artifact folder, so a file Defender scanned is the file "Open" opens.
- **Extension pages open only from their toolbar button.** A website (or an agent through one) can no longer open an extension's pop-up or options page, and a pop-up window that navigates to a website loses the extension's endpoints and storage.
- **Save sign-in**: a sign-in typed into another site's embedded frame is no longer offered for the page around it, and `credentials.fill` stops if the page moved to another site before typing.
- **Offer to save sign-ins** can be switched off again (the switch was refused as a "secret" setting).
- One extension's content scripts can no longer change another extension's storage.
- Approvals the person granted expire after five minutes, and an agent can have at most 20 waiting.
- `device.web_authn` (a virtual passkey device) asks the person first.
- Pages can no longer detect AgentGo through its hidden markers (ad blocking keeps none; dark mode and fingerprint protection hide theirs from `Object.getOwnPropertySymbols`, `Reflect.ownKeys` and `Object.getOwnPropertyDescriptors`; no `DarkReader` global).
- Downloads named like Windows devices (`NUL`, `CON.txt`, `COM1`) are saved as `_NUL` and so on.
- Notifications an agent raises say they come from the agent.
- A dangerous site the person opened anyway stays blocked in tabs an agent holds or drives.
- `agentgo setup claude|codex|droid` and Setup run the agent host's program directly, so an install path with `&` or `^` works.
- Passwords typed into a tab are forgotten when it closes.

## 0.1.3 (2026-10-18)

- **Extension pop-ups**: clicking a pinned extension opens its own pop-up (the toolbar window it shows in Chrome) instead of the Extensions panel; the panel has Open and Options buttons. Pages are served from the extension's own origin (`agentgo-ext://<id>/`) with `chrome.runtime`, `chrome.i18n`, `chrome.storage` (shared with its content scripts), `chrome.tabs.query`/`create` and `openOptionsPage`. Websites cannot load an extension's files or endpoints, and agents cannot open extension pages. Background workers do not run yet; pop-ups of extensions that need one say so (`extension.open_popup`, operator only).
- **No console window**: AgentGo no longer leaves a Command Prompt window on the desktop when it is started from a shortcut or another program; it runs in the background with only the browser window showing (`AGENTGO_KEEP_CONSOLE=1` keeps it for debugging).
- **Signed with Sigstore Cosign**: every file on the release carries a keyless Cosign signature bundle (`<file>.sigstore.json`), made by the repository's `sign-release` workflow and recorded in the public Rekor log. `docs/verify-release.md` shows how to check a download. This proves where a file came from; it is not an Authenticode signature, so SmartScreen may still ask.

## 0.1.2 (2026-10-18)

- **GoMini, the local model**: a 322M-parameter model trained on AgentGo's own decision records ([huggingface.co/Mhmadhassnz/GoMini](https://huggingface.co/Mhmadhassnz/GoMini)) takes the routine steps of a task on your computer. An agent hands it one subgoal (`gomini.delegate`, over MCP `browser_delegate`) with the values to type and how to tell it is done; GoMini fills, clicks, checks, selects, scrolls and waits, and returns `done`, `needs_help` or `stopped` with every step. Each choice is checked independently before it runs (offered candidate, page revision, supplied value, same site, no payment, sign-in, submission, delete or other sensitive step), typed fields are read back, Pause and Stop apply, and the browser's own approvals still hold. GoMini sees exactly the input it was trained on (token-identical to the reference packer).
- **Getting GoMini**: AgentGo Setup offers it (on by default, about 390 MB, `--no-gomini` for silent installs); Settings > GoMini has an animated Download button that becomes its own progress bar, then the Activate switch, the device it runs on and Remove. The runtime is upstream llama.cpp b11559: the Vulkan build on any graphics card that shows up (AMD, NVIDIA, Intel), else the processor build, chosen after a real test decision. Every file is pinned by SHA-256; downloads resume. On a Radeon RX 7800 XT one decision takes about 15 ms (processor: about 450 ms).
- **Agents learn GoMini**: when it is on, MCP lists `browser_delegate` and the server's instructions say to use it; the skill has a GoMini guide (`references/gomini.md`, `browser_guide topic=gomini`). `decision.status` reports it. The decision record is version `agentgo.gomini.decision/1` (the model was called Laya; `topic=laya` still answers).
- **Decision record fixes**: `recent` holds only the caller's own session's commands (another agent's activity leaked into it, AG-001); `state.status` carries visible status, alert and live-region text that compact outlines leave out (AG-L01).
- **New tabs**: over MCP, `tabs.create` now shows the new tab's id; the reply says `loading: true` with how to wait, or with `wait: true` waits for the page and reports `loaded` (AG-L02).
- **Clear history by time**: Last hour, Last 24 hours, Last 7 days, Last 4 weeks or All time.
- **Chrome Web Store**: "Add to Chrome" works again. The store wanted `chrome.management` and Google Chrome's brand before offering the button (it showed "Switch to Chrome?"); AgentGo provides both on the store's pages only. A person's click is no longer refused just because an agent is connected (the store then showed "Download error: undefined"); an agent's click still is. When an extension cannot run in AgentGo, you are told why.
- **Import extensions from Chrome**: the import lists the profile's Web Store extensions and installs each fresh from the store (signature checked); ones AgentGo cannot run are named with the reason.
- `rustls` 0.23.46 (build-time download tool only).

## 0.1.1 (2026-10-17)

- **AgentGo Setup**: a graphical installer (`AgentGo-Setup.exe`, and an offline `AgentGo-Setup-full.exe`). A floating card on a transparent window that unfolds from the AgentGo mark; license, folder, shortcuts, PATH, agent registration (Claude Code, Codex, Droid), preferences, an install that checks every file against its SHA-256, import from your old browser, and an uninstaller in Windows Settings. Per user, no administrator rights. `--silent` installs and uninstalls without a window for scripted deployments.
- **Fingerprint protection, hardened**: the hooks are proxies of the native functions (they read as `[native code]`, with the right name and length); blank and `srcdoc` iframes and `window.open` popups are covered; `OffscreenCanvas` and `AudioBuffer.copyFromChannel` reads are covered; noise is keyed to the pixel position; spoofed CPU and memory numbers are dropped (workers reported the real ones, and the mismatch itself identified the browser).
- **Fingerprint modes fixed**: the first page of a new tab was unprotected, and switching between the person's mode and the agent's mode could be lost when it raced a running install. Both fixed and tested, including that the agent keeps its fingerprint across restarts.
- **Dangerous-site protection**: every page is checked before it loads against 35,000+ known malware and phishing hosts (URLhaus, uBlock Badware, Phishing URL Blocklist from OpenPhish, PhishTank and IPThreat) and by look-alike detection that needs no list: letters from other alphabets (`pаypal.com`), a brand's domain used as a subdomain (`paypal.com.verify.top`) and a brand next to a lure word (`paypal-login-secure.com`). Checked on this computer; no address is sent anywhere. Zero look-alike false positives across the 100,000 most visited sites. Blocked pages show a warning; the person may open one anyway, an agent never can (not even after disconnecting: a click that came with agent input is refused).
- **More privacy by default**: third-party cookies blocked; tracking parameters (`fbclid`, `gclid`, `msclkid`, `utm_*` and 40 more) removed from addresses before the request; the Global Privacy Control signal sent (`Sec-GPC: 1`, `navigator.globalPrivacyControl`); notification requests refused. Each has a switch in Settings, Privacy.
- **WebRTC**: pages only ever learn the default route's public address (`default_public_interface_only`); private interfaces and VPN adapters stay hidden.
- `browser.launch` reports the browser's own process id (it reported a launcher that had already exited).
- **Import**: Chrome passwords saved to the Google account (`Login Data For Account`) are imported; profile counts no longer read 0 while the other browser is open; the history limit is 20,000 and the sign-in vault holds 5,000 sign-ins. Passwords Chrome seals with app-bound encryption come over through Chrome's own export: the import offers "Open Chrome export" and "Choose CSV file". New `agentgo import` command (scan, import, `--csv`, `--open-export`).
- **MCP**: `agentgo setup claude` registers for the user (every project), not only the current folder; `agentgo setup droid` no longer stores the path without its backslashes (Droid could not start AgentGo).
- **Automatic updates**: AgentGo checks the latest GitHub release shortly after it starts and every six hours. A new version must carry AgentGo's Ed25519 release signature and match its SHA-256; it downloads in the background and goes in when you close AgentGo (a "Restart to update" button does it now). With "Update automatically" off (Settings, About, or in Setup), an "Update to x.y.z" button appears in the toolbar instead. Installed copies update through AgentGo Setup with the same film as installing ("Updating", then "Updated to x.y.z"), shown once AgentGo has closed. Updates replace only the program folder: profiles, saved sign-ins, accounts, history and settings live in `%LOCALAPPDATA%\AgentGo` and are never touched, and Setup refuses any folder that holds them. The uninstaller and the Windows version entry survive updates; `browser.update_rollback` goes back. (The on-exit swap used to give up after two minutes; it now waits for AgentGo to close.)
- **Developer tools**: a close button in their corner (F12 inside them closes too); right-click Inspect while they are open inspects the new element instead of closing them; closing them, or closing a tab with them open, no longer blanks the toolbar or the window (D88).
- **Extensions**: the Chrome Web Store's own "Add to Chrome" button now installs into AgentGo (it used to start the engine's internal install, which never finished and never reached AgentGo's pages; only the person's click on that extension's own page counts). Extension content scripts get `chrome.runtime`, `chrome.i18n` and `chrome.storage` (saved across page loads); extensions that need a background page are labelled as limited. Packages signed with older 1024-bit keys (Google Translate) install (D89).
